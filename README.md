## 一、系统简介

本系统是一个面向民航领域的**航班调度算法可视化系统**，以四川航空（川航）为业务背景，覆盖从"客流量 → 航班计划 → 任务链 → 飞机排班 → 跑道调度 → 登机口分配 → 机组排班 → 异常恢复 → 运行仿真"的完整业务链路。

系统核心能力：

| 模块 | 解决的问题 | 核心算法 |
|------|-----------|---------|
| 航班生成 | 由城市间客流量生成航班计划、旅客清单、任务链 | 方向客流贪心排班 + 航班批次合并 |
| 航班筛选 | 从上传数据中筛出能组成"基地闭环"的航班 | 任务链搜索（DFS/BFS） |
| 飞机排班 | 用最少飞机覆盖全部航班 | 二分图匹配 / 贪心 / VRP 平衡贪心 / 链集合覆盖 |
| 跑道调度 | 优化起降顺序，减少延误 | FCFS / CP-SAT / ILS-CPS 优化排序 |
| 登机口分配 | 为航班分配登机口，减少旅客步行 | 评分贪心 / 二分图 / CP-SAT 局部搜索 |
| 机组排班 | 组建 5 人机组（1 机长+1 副驾+1 乘务长+2 乘务员），满足 CCAR 法规 | 逐航班贪心 / Pairing / 飞机链切割 |
| 异常调度 | 天气/机场/飞机/机组异常的影响分析与恢复 | 影响传播分析 + 5 种恢复策略 |
| 运行仿真 | 航班实时运行动画、天气联动、旅客粒子流 | 仿真引擎 + 统一时钟驱动 |

## 三、系统启动

系统由 **后端（Flask）** 和 **前端（Vue）** 两部分组成，需分别启动。

### 3.1 环境准备

需要安装：
- Python 3.12+
- Node.js（含 npm，建议 16+）

### 3.2 启动后端

```powershell
# 1. 进入项目根目录
cd d:\Desktop\job-data-visualization-team-master

# 2. 安装后端依赖（建议使用虚拟环境）
pip install flask flask-cors ortools xlrd openpyxl

# 3. 启动后端（注意：必须用 python -m backend.app 方式启动，
#    因为后端使用了相对导入）
python -m backend.app
```

启动成功后终端显示：

```
==================================================
  川航航班调度系统 - 后端服务
  地址: http://0.0.0.0:5000
==================================================
```

后端默认监听 `5000` 端口（见 `backend/config.py`，`DEBUG=False`）。

> 健康检查：浏览器访问 `http://127.0.0.1:5000/api/health`，返回 `{"code": 0, "msg": "ok"}` 即后端正常。

### 3.3 启动前端

```powershell
# 1. 进入前端目录
cd d:\Desktop\job-data-visualization-team-master\demo

# 2. 安装依赖
npm install

# 3. 启动开发服务器
npm run serve
```

启动成功后浏览器访问 **http://localhost:8080**（Vue 开发服务器默认端口，若被占用会自动 +1）。

前端已配置代理（`demo/vue.config.js`）：所有 `/api` 请求自动转发到 `http://127.0.0.1:5000`，因此**必须先启动后端**，前端页面才能正常加载数据。

> 生产构建：`npm run build` 生成静态文件到 `demo/dist/`，可用任意静态服务器托管（由于 `publicPath: "./"`，dist 目录可直接双击 `index.html` 或部署到任意路径）。

### 3.4 启动顺序总结

1. 启动后端 → 2. 启动前端 → 3. 浏览器打开 `http://localhost:8080` → 4. 登录。

## 四、登录说明

打开系统后首先进入登录页（`/login`）。

**预设账号（两对均可使用）：**

| 用户名 | 密码 |
|--------|------|
| `user1` | `user1` |
| `user2` | `user2` |

- 输入账号密码后点击"登 录"按钮，调用 `POST /api/auth/login` 验证。
- 登录成功后跳转首页；关闭浏览器后再次访问需要重新登录（登录状态保存在 localStorage）。

## 六、各页面使用详解

### 6.1 首页 Home

首页是系统门户，分左右两区：**左侧"分析历史"**、**右侧"航班计划上传"**。

**功能与操作：**

1. **上传航班计划（右侧）**
   - 点击上传区选择 `.xlsx` 文件（航班计划格式见"第十章"）。
   - 上传后显示解析进度条，解析完成自动进入分析工作台（航班筛选页）。
   - 上传后即可在"航班筛选"页执行筛选。

2. **分析历史（左侧）**
   - 列表展示当前用户的所有历史记录（文件名、上传时间、航班数、活跃航班数、任务链数）。
   - 点击某条历史记录 → 加载该记录的数据并进入分析工作台。
   - 每条记录右侧有删除按钮，可删除该历史记录。

3. **快捷入口（页面右/左上角）**
   - "客流量输入" → 进入客流量生成航班计划流程。
   - "旅客追溯" → 按旅客 ID 查询旅客行程。
   - "边界说明" → 查看系统法规依据。
   - "退出登录" → 清空登录状态返回登录页。

### 6.2 客流量输入 TrafficInput

通过**城市对方向的日客流量**自动生成航班计划（适用于没有现成 xlsx 的场景）。

**操作步骤：**

1. 配置全局参数：
   - 目标枢纽：固定为"成都"。
   - 机队：A319 × 10 / A320 × 50 / A321 × 40（数量可改，需合计约 100 架）。
   - 客座率（默认 78%）、过站时间（默认 60 分钟）、单日最大段数、日期范围（默认 2020-11-30 ~ 12-05）。
   - 川航基地多选（成都/重庆/昆明/杭州/绵阳/宜宾等）。

2. 填写**方向客流明细表**：每个"起始站 → 到达站"方向填日客流量（人/天）；表头有"加载演示数据"和"全部清零"按钮。

3. 查看**城市进出港汇总表**：自动汇总各城市进港/出港总量，便于核对。

4. 点击底部"**生成航班计划**"按钮，调用 `POST /api/generate/flights`；成功后跳转"航班计划总览"页。

### 6.3 航班计划总览 ScheduleOverview

以**任务链**形式展示上一步生成的航班计划，供人工核对与确认。

**操作步骤：**

1. 查看顶部 KPI 卡片：总航班数、任务链数、覆盖城市、总旅客、总座位、空飞数（调机）。
2. 查看任务链列表：可折叠展开；每条任务链显示航班段序列（出发地 → 到达地、时间、机型）。
   - 每段航班右侧"查看旅客"按钮 → 跳转航班旅客明细页（3D/2D 座位图）。
   - 空飞（无旅客）航班以红色标注。
3. 左上"返回修改" → 返回客流量输入页调整参数。
4. 右上"**确认并进入调度**" → 调用 `POST /api/generate/commit` 提交计划（生成一条历史记录），并跳转分析工作台。提交后系统即可执行飞机排班等调度。

### 6.4 航班计划筛选 FilterView

对**上传的航班计划 xlsx** 进行筛选，剔除无法组成"基地闭环"的不合格航班，生成任务链池。这是分析工作台内嵌的"航班筛选"标签页。

**操作步骤：**

1. 点击"**上传航班计划 xlsx**"选择文件（若在首页已上传可跳过）。
2. 点击"**执行筛选**"：系统自动搜索能组成基地闭环（首尾都在川航基地）的任务链，最多 300 条。
   - 左侧"任务链池"：分页展示筛选出的任务链，点击可查看链内航班明细，支持"加载更多"。
   - 右侧"不合格航班表"：展示孤儿航班/无法成链的航班及原因（如无基地衔接、时间冲突等）。
   - 顶部统计：总航班数、合格航班数、孤儿航班数、任务链数、城市覆盖率。
3. 点击"**保存并执行排班计划**"（`POST /api/flights/apply`）：将筛选结果保存为活跃数据源并触发后续排班。
4. 点击"**导出 xlsx**"：下载仅含任务链航班的筛选结果文件（保留原文件格式并附带统计 Sheet）。

> 注意：只有"保存并执行排班计划"之后，飞机排班/跑道调度等页面才会基于筛选后的数据运行。

### 6.7 飞机排班 GanttView

为任务链分配飞机，生成"飞机 × 航班"甘特图。这是四大调度功能之一。

**操作步骤：**

1. 选择算法（下拉框）：
   - **二分图匹配（bipartite）**：匈牙利算法最大匹配，路径首尾必须为基地。
   - **贪心算法（greedy）**：逐架飞机扫描分配。
   - **均衡分配（vrp）**：平衡贪心，负载最低优先。
   - 说明：在已保存筛选结果（任务链池）的情况下，默认走"链集合覆盖"（每架飞机整链执飞，航司标准做法）。
2. 设置参数：飞机数上限（默认 100）、机场筛选、日期、飞机搜索框。
3. 点击"**一键排班**"：调用 `POST /api/schedule/routing`，生成甘特图。
   - 每行一架飞机，色块为航班（含航班号、起降时间）。
   - 若某飞机当日执勤超 480 分钟，行左侧标红（CCAR-121 限制）。
4. 点击"**算法对比**"：对比二分图/贪心/链覆盖三种算法的飞机数、利用率、空闲时间。
5. 点击甘特图上的航班色块：弹出航班详情（航班号/航线/起降时间/延误）。
6. 点击某飞机行的"**调整**"按钮：弹出该飞机指标编辑框（机龄、总飞行小时、年维护天数、小时成本、燃油效率、准点率、大修日期、循环次数），保存后系统按新指标重算质量指数并自动重新排班。
7. 选择日期后点击"**保存排班**"：保存当前飞机排班方案，供地图演示使用。

## 七、调度功能详解（算法与参数）

### 7.1 飞机排班

| 算法 | 说明 |
|------|------|
| 二分图匹配 bipartite | 构建同机型+时间衔接邻接矩阵，匈牙利算法最大匹配 → 路径覆盖，路径首尾必须为基地才建飞机 |
| 贪心 greedy | 逐架飞机扫描（机型匹配+首班基地出发+衔接+日上限），最后闭环过滤 |
| 均衡分配 vrp | 按出发时间排序，机型匹配+负载最低优先+衔接最紧次优先，轮询分配 |
| 链集合覆盖 chain_coverage | 筛选后自动启用：只保留基地闭环链，按链总飞行分钟降序贪心选互不重叠链，每链整链给一架飞机；飞机按质量指数降序，最重链配最好飞机 |

**关键约束：**
- 川航基地：成都、重庆、昆明、宜宾、绵阳、杭州。
- 每架飞机首班必须从基地出发、末班必须回基地（基地闭环）。
- 单机日上限（由质量指数决定 `max_daily_flights`）。
- 前后航班衔接最小间隔 `min_gap`（默认 60 分钟）。

**统计指标：** 在用飞机数、航班覆盖率（%）、平均利用率、总空闲时间、基地分布、闭环飞机数。

### 7.2 跑道调度

| 方法 | 说明 |
|------|------|
| FCFS | 按目标时间贪心分配最早空闲跑道 |
| CP-SAT | 按机场分组独立约束求解 |
| ILS-CPS | 先 FCFS 分配，再对每条跑道内做局部搜索（相邻交换，限制位置偏移 ≤ 3）最小化总延误 |

**关键规则（依据 CCAR-93）：**
- 跑道：成都双流配置 02L / 02R 两条。
- 尾流类别：重型（A330/A340/A350/A380/B767/B777/B787/B747）、中型（A319/A320/A321/B737/...）、轻型。
- 尾流间隔：重型后随重型 2 分钟、重型后随中型 3 分钟、重型后随轻型 4 分钟、中型后随轻型 3 分钟等（`backend/config.py` 的 `MIN_SEPARATION`）。
- 跑道占用时长：重型 3 分钟、中型 2 分钟。

**统计指标：** 总起降数、降落/起飞数、总延误、平均延误、各跑道负载。

### 7.3 登机口分配

| 算法 | 说明 |
|------|------|
| 贪心 greedy | 逐航班选第一个可用兼容机位（评分最优） |
| 二分图 bipartite | 与 greedy 近似的"评分贪心"实现 |
| CP-SAT | 先初始化可行解，再迭代局部搜索（≤500 轮/25s）：从最大负载机位移走航班、双机位交换，降低最大负载 |

**评分因素（得分越低越好）：** 机型匹配（完美 0/降级 5/越级 8-12）+ 负载均衡 + 滑行成本（(进+出)×3）+ 跑道归属（非本跑道组 +30）。
**冲突检测：** 同机位相邻航班 `start < 前机end` 即冲突。
**统计：** 总机位、已用机位、平均/最大/最小利用率。

### 7.4 机组排班

| 模式 | 说明 |
|------|------|
| 逐航班贪心（legacy） | 按出发时间排序逐日分配：机长/副驾/乘务长各 1 + 乘务员 2 |
| Pairing | 从航班 DFS 生成 pairing（任务链）再指派机组 |
| 基于飞机链 chain | 把飞机链按法规切割成 2-4 段短 pairing（执勤 ≤14h 一组，过夜间隔 ≥6h 强制切割）再指派 |

**法规约束（CCAR-121）：**
- 5 人机组：1 机长 + 1 副驾 + 1 乘务长 + 2 乘务员。
- 日飞行小时上限、日执勤 ≤ 14 小时、7 天滚动飞行 ≤ 40 小时。
- 前后航班间隔缓冲 ≥ 30 分钟（MIN_CREW_GAP）。
- 机型资质匹配（crew_roster.json 中的 qualifications）。

**合规报告指标：** 总人数、已排班人数、违规数、违规明细（超时/超限）、机组分组（team_groups）。

## 八、模拟与联动功能详解

### 8.1 仿真引擎

- **初始化**：加载当前活跃航班，计算航线距离（haversine）、巡航时长（按机型巡航速度）、各飞行阶段耗时，生成航班状态；仿真时间范围 = 最早起飞 ~ 最晚到达 + 240 分钟。
- **控制**：启动/暂停/恢复/停止/单步/倍速（1-10x）/跳转到任意时刻。
- **状态机**：SCHEDULED → PUSH_BACK → TAKEOFF → CRUISE → DESCENT → LAND → ARRIVED → PARKED（DELAYED 为延误状态）。
- **机场容量**：每机场容量系数（默认 1.0）；起飞前容量 < 0.5 时按概率延误 30 分钟。
- **KPI**：准点率、完成率、空中/延误/取消航班数、总旅客、延误旅客、平均延误、活跃异常数。
- **统一时钟（sync_to）**：模拟大引擎模式下，前端天气时钟作为唯一时间源，引擎按绝对业务分钟确定性重算航班状态，并叠加当前天气中断计划。

### 8.2 天气中断联动

前端天气页每 2 秒回传各省天气 + 气旋推演时间线 → 后端计算天气中断计划：

- **天气 → 容量/严重度映射**：晴朗(1.0/0)、多云(0.9/0)、小雨(0.8/1)、中雨(0.7/2)、大雨(0.5/3)、雷暴(0.4/4)。
- **受影响航班**：起降省份受灾（直接受影响）+ 航线途经受灾省份（途经受影响）。
- **处置规则**：
  - 直接受影响航班：委托影响分析算法，延误 ≥ 5 小时则取消，否则延误；
  - 途经航班：统一加延误 `30 + 10 × max(1, 严重度)` 分钟（绕飞）；
  - 只影响起飞时间落在坏天气窗口内的航班。
- 中断计划写回共享状态，**航班模拟、旅客流模拟、总览仪表盘实时联动**（延误/取消状态同步）。

### 8.3 事件注入（模拟场景）

| 事件 | 参数 | 效果 |
|------|------|------|
| 机场异常 | 机场、容量比（0-1）、时长 | 机场容量下降，影响起飞/降落 |
| 机组请假 | 人员名单、起止时间、航司、基地 | 相关航班机组资源缺口 |
| 飞机故障 | 尾号、时长 | 该机停飞，航班重新安排 |

### 8.4 旅客流模拟

- 数据源：最近一条 `gen_*` 历史记录中的成都场航班，执行真实跑道调度 + 登机口分配，按"矩形登机口"映射到前端航站楼布局。
- 载客率默认 78%；乘客编号形如 `Pax-1130-00001`。
- 支持旅客流量调节、闸门/路段控制、拥堵热力图、应急疏散。

### 8.5 模拟大引擎（统一时钟）

三个子场景（航班模拟/天气/旅客流）共用业务时钟：纪元 2020-11-29 00:00，周期 7 天（10080 分钟），1x = 5 业务分钟/秒。播放/暂停/倍速/拖拽跳转由底部统一时钟控制条操作。

## 九、异常调度流程详解

### 9.1 完整流程

```
新建异常事件 → 影响分析（生成影响报告 + 恢复方案草稿）
  → 确认方案（草稿→已确认）
  → 执行方案（后台执行 + 进度轮询 + 自动重排班）
  → 已执行（可回滚，也可人工微调）
```

### 9.2 异常场景模板

| 分类 | 模板示例 |
|------|---------|
| 天气（机场） | wx_001 成都双流雷暴关闭、wx_002 重庆江北大雾、wx_003 昆明长水暴雪、wx_004 航路雷暴绕飞 |
| 天气（省份） | wp_001 台风广东沿海、wp_002 四川盆地雷暴、wp_003 华中三省暴雨 |
| 飞机 | ac_001 A319 机械故障 AOG、ac_002 飞机备降、ac_003 例行定检延期 |
| 机组 | cr_001 机组请假替班、cr_002 执勤超时、cr_003 资质不匹配 |
| 跑道 | rw_001 跑道维修关闭、rw_002 跑道灯光降级 |
| 登机口 | gt_001 廊桥故障关闭、gt_002 登机口被占用未释放 |
| 空域/流控 | fc_001 成都流控限制、fc_002 空域临时关闭 |

### 9.3 恢复策略

| 策略 | 适用场景 | 说明 |
|------|---------|------|
| 取消航班 CancelFlights | 兜底 | 延误 ≥ 360 分钟且未被覆盖的航班追加取消，级联优先 |
| 任务链重排 ChainReplanning | 飞机故障/多机受影响 | 受影响飞机的孤儿航班插入健康飞机空闲时段（过站 ≥ 45 分钟，同机型） |
| 航班合并 MergeFlights | 影响航班 ≥ 4 | 起飞差 ≤ 120 分钟、同出发同目的地的航班合并（保留早班） |
| 资源替换 ResourceReplacement | 有受影响资源 | 从备份资源池（飞机/机组/登机口/跑道）替换 |
| 时间平移 TimeShift | 机场/跑道关闭后恢复 | 从链内首个受影响航班起整链平移，递推累加，间隔 ≥ 30 分钟 |

### 9.4 恢复方案执行后的动作

- **飞机异常**：排除故障飞机后，用剩余飞机重新做链集合覆盖。
- **机组异常**：执行机组替班（同基地同角色无冲突者），应用替班变更到机组池。
- **其他**：从航班/任务链中删除取消航班、对延误航班改写起降时间，然后重跑"任务链筛选 → 飞机排班 → 机组排班"。
- 结果持久化到历史记录的 `result.json`。

### 9.5 审计日志

所有关键操作（创建事件/分析/确认/拒绝/执行/回滚/人工微调）都会写入审计日志，保存在历史目录的 `audit_logs/` 下，可在异常调度页右栏"调度日志"查看。

## 十、数据格式与上传要求

### 10.1 航班计划 xlsx（上传）

上传文件支持 `.xlsx`（`.xls` 亦兼容），单文件 ≤ 50MB。系统自动在**前 10 行内查找表头行**（包含 `FLIGHT_ID` 的行），支持以下列（列名大小写不敏感，按包含匹配）：

| 列名 | 必填 | 说明 |
|------|------|------|
| FLIGHT_ID | 是 | 航班唯一 ID（整数） |
| FLIGHT_NO | 是 | 航班号（如 3U8001） |
| AC_TYPE | 否 | 机型（默认 A319，支持 A319/A320/A321 等） |
| LAYOUT | 否 | 客舱布局（默认 C8Y124；A320=C8Y156、A321=C8Y186） |
| DEPARTURE_AIRPORT | 是 | 出发机场（中文名或 ICAO 码，ICAO 码自动转中文） |
| ARRIVAL_AIRPORT | 是 | 到达机场（同上） |
| STD / TIME_DEPARTURE | 是 | 计划起飞时间 |
| STA / TIME_ARRIVAL | 是 | 计划到达时间 |
| TIMESPAN | 否 | 飞行时长（分钟），缺省按起降时间推算 |
| COST | 否 | 成本（浮点） |

**时间格式支持：**
- Excel 日期时间（datetime 对象 / 浮点序列号）；
- `2020-11-30 06:00` / `2020-11-30 06:00:00`；
- `30/11/2020 08:45:00`；
- `2020,11,30,6,0`。

> 项目内置示例数据：`data/final_test/upload.xlsx`、`data/api_test2/upload.xlsx`。

### 10.2 其他数据文件（backend/data/）

| 文件 | 用途 |
|------|------|
| aircraft_index.json | 机队综合质量指数（飞机排班按指数降序分配） |
| airports_runway.json | 各机场跑道配置 |
| airports_gates.json | 各机场登机口组配置（跑道→登机口范围、滑行时间） |
| crew_roster.json | 机组名册（航司→基地→机长/副驾/乘务长/乘务员名单与资质） |

## 十一、历史记录管理

- **存储位置**：`data/history/{用户名}/{历史ID}/`，每个历史记录目录包含：
  - `upload.xlsx`：原始上传文件；
  - `flights_cache.json`：解析后的航班缓存（秒级加载）；
  - `result.json`：筛选结果（航班 + 任务链，含恢复执行后的数据）；
  - `meta.json`：元信息（文件名、上传时间、航班数、任务链数）；
  - `audit_logs/`：审计日志（异常调度相关）。
- **管理方式**：首页左侧"分析历史"列表查看/点击加载/删除。
- **生成记录**：上传航班并保存筛选结果，或"客流量 → 确认并进入调度"都会创建一条历史记录。
- **恢复方案持久化**：异常恢复执行完成后，`result.json` 与 `meta.json` 会更新（标记 `recovery_applied` 并记录恢复时间）。
- **兼容性**：后端启动时会自动把旧版无用户目录的历史记录迁移到 `user1` 名下。

## 十二、常见问题与注意事项

1. **页面没有数据/报"请先上传或筛选航班"**
   - 先在首页上传 xlsx，或在"航班筛选"页执行筛选并"保存并执行排班计划"。
   - 确认后端已启动（`http://127.0.0.1:5000/api/health` 返回 ok）。
2. **上传报"仅支持 .xlsx 格式"**
   - 检查文件后缀；确认文件为真正的 Excel 文件而非改后缀的 CSV。
3. **"保存排班/保存跑道"提示缺少日期**
   - 保存类操作前必须先在页面选择日期。
4. **飞机排班"一键排班"后甘特图为空**
   - 可能当前没有已保存的筛选结果；先到航班筛选页保存。
   - 或检查当前任务链是否满足基地闭环约束。
5. **异常恢复执行后数据变化**
   - 恢复执行会修改航班/任务链数据，其他页面（地图、模拟等）需刷新；系统会发出 `filter-needs-refresh` 事件提示。
6. **登录后无法访问页面**
   - 确认 localStorage 中有 `current_user`；如异常可清除浏览器站点数据后重新登录。
7. **端口冲突**
   - 后端固定 5000、前端默认 8080；若被占用，前端会自动 +1（注意浏览器实际端口），后端可改 `backend/config.py` 的 `PORT`。
8. **模拟大引擎无航班**
   - 先初始化仿真：进入"航班模拟"标签点击"🚀 启动仿真"；或确认已有活跃航班数据。
9. **天气页手动输入模式**
   - 手动模式下修改省份天气立即生效；要恢复推演需切回"动态演示"模式。
10. **3D 页面黑屏**
    - 确认浏览器支持 WebGL；模型文件位于 `demo/public/models/`。
