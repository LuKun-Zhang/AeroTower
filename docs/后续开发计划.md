# 模拟引擎开发计划

> **目标**：构建一个基于地图视角的航班运营模拟引擎，支持时间推进、异常事件注入、航班调度及旅客流的端到端仿真  
> **核心策略**：异常事件直接复用已实现的四种异常类型（天气/机场/机组/飞机），触发后走现有恢复方案流程，不做重复开发  
> **原则**：最大化复用已有组件（地图、飞机动画、航班数据、恢复方案），每个模块先跑通核心链路再迭代

## 第一阶段：引擎核心 — 时钟 + 航班状态机 + 航路计算（3 天）

### 仿真时钟
- **引擎入口**：`SimulationEngine` 类，管理仿真生命周期
- **控制**：启动 / 暂停 / 恢复 / 停止 / 单步
- **粒度**：1 tick = 1 仿真分钟，支持 1x / 2x / 5x / 10x 加速
- **时间范围**：从数据集中最早航班出发时间到最晚到达时间
- **每 tick 执行顺序**：
  1. 推进所有航班状态机
  2. 检查天气变化事件
  3. 处理待注入的手动异常事件
  4. 更新机场容量（受天气 + 机场异常影响）
  5. 检测航班冲突 → 标记 DELAYED / CANCELLED
  6. 更新旅客状态
  7. 汇总 KPI
- **验收**：前端可播放/暂停/调速，地图上飞机随时间移动

### 航班状态机
- **正常状态序列**：`SCHEDULED → PUSH_BACK → TAXI_OUT → TAKEOFF → CLIMB → CRUISE → DESCENT → APPROACH → LANDING → TAXI_IN → PARKED`
- **状态转换条件**：
  | 转换 | 条件 | 耗时 |
  |------|------|------|
  | SCHEDULED → PUSH_BACK | 计划出发时间到达 | 即时 |
  | PUSH_BACK → TAXI_OUT | 固定耗时 | 3-5 min |
  | TAXI_OUT → TAKEOFF | 跑道空闲 + 滑行耗时 | 5-8 min |
  | TAKEOFF → CLIMB → CRUISE → DESCENT → APPROACH | 航路计算确定 | 计算值 |
  | APPROACH → LANDING | 跑道空闲 | 3-5 min |
  | LANDING → TAXI_IN → PARKED | 固定耗时 | 5-8 min |
- **异常状态**：
  - `DELAYED`：出发推迟（触发：天气/流控/前序晚到/飞机故障）
  - `CANCELLED`：航班取消（触发：严重天气/飞机不可用/机场关闭）
- **验收**：任意航班可追踪当前状态，状态变更产生事件日志

### 航路计算
- **公式**：Haversine 大圆距离 / 机型巡航速度 = 航路飞行时间
- **拆分为**：爬升 ~15min + 巡航（计算值）+ 下降 ~15min
- **复用**：已有 `airports.json` 全部机场坐标
- **验收**：给定两个机场，算出合理飞行时间

## 第二阶段：异常事件注入 — 四种已有类型（3 天）

> **核心策略**：模拟中的异常事件直接复用已实现的四种类型 → 触发 `analyze` + `execute` 流程 → 调用已有恢复方案逻辑（机组替班/飞机排除/机场容量调整等），零重复开发。

### 2.1 天气异常（自动模拟）

天气由系统随机生成，模拟过程中自动触发，无需用户干预。

- **生成方式**：引擎每 tick 检查是否有天气变化事件
- **天气类型**：
  | 类型 | 能见度 | 影响 |
  |------|--------|------|
  | CLEAR 晴 | > 5000m | 无影响 |
  | CLOUDY 多云 | 3000-5000m | 跑道容量 -10% |
  | RAIN 雨 | 1000-3000m | 跑道容量 -30% |
  | THUNDERSTORM 雷暴 | 500-1000m | 跑道容量 -60%，航班可能取消 |
  | FOG 雾 | < 500m | 跑道容量 -80%，大面积延误 |
- **变化规则**：每小时按马尔可夫概率转移，倾向逐步恶化再恢复
  ```
  CLEAR → CLOUDY (30%) → RAIN (20%) → THUNDERSTORM (10%)
  THUNDERSTORM → RAIN (50%) → CLOUDY (40%) → CLEAR (30%)
  ```
- **区域相关性**：相邻机场天气变化有概率联动（如成都变 RAIN → 重庆 40% 概率也变 RAIN）
- **触发时机**：天气恶化到 RAIN 及以上 → 引擎自动创建天气异常事件 → 调用已有 analyze/execute → 容量下降生效
- **天气好转**：天气恢复到 CLEAR/CLOUDY → 自动解除容量限制 → 逐步消化积压航班

### 2.2 机场异常（手动注入）

用户从事件注入面板手动选择机场触发。

- **注入面板**：地图页右侧工具栏的"异常注入"按钮，弹出 Dialog
- **选择参数**：
  - 机场：下拉选择（全部航班机场）
  - 影响程度：轻度（容量 -30%）/ 中度（容量 -50%）/ 重度（关闭，容量 = 0）
  - 持续时间：15min / 30min / 1h / 2h / 自定义
  - 生效时间：立即 / 指定时间
- **后端处理**：创建 `AnomalyEvent`（event_type=`airport`）→ `recovery_service.generate_recovery_plan()` → 容量调整
- **效果**：指定机场起降容量按比例下降，触发航班 DELAYED / CANCELLED
- **到期自动恢复**：到达持续时间后自动还原容量

### 2.3 机组请假（手动注入）

用户从事件注入面板手动选择机组人员触发，直接复用已有替班逻辑。

- **注入面板**：选择机组人员，Dialog 显示可用机组列表
- **选择参数**：
  - 航司：下拉选择（四川航空/南方航空等）
  - 基地：下拉选择（成都/重庆/昆明等）
  - 人员：按角色（机长/副驾驶/乘务长/乘务员）展示列表，勾选请假人员
  - 请假时段：起始时间 + 结束时间
- **后端处理**：
  1. 创建 `AnomalyEvent`（event_type=`crew_absence`，affected_crew 写入选中人员）
  2. 调用已有 `recovery_service.generate_recovery_plan()` → 查找替班
  3. 生成 `CrewSubstitutionRecovery` 方案
  4. 用户确认后调用 `execute_plan()` → 已有替班流程接管
- **复用链路**：完全复用 `analyze_event` + `execute_plan` + `_on_recovery_executed` + `schedule_crew` 整条链路

### 2.4 飞机故障（手动注入）

用户从事件注入面板手动选择飞机触发。

- **注入面板**：选择飞机，Dialog 显示可用飞机列表
- **选择参数**：
  - 飞机注册号：下拉选择（B-xxxx）
  - 故障开始时间
  - 预计修复时长：1h / 2h / 4h / 自定义
- **后端处理**：
  1. 创建 `AnomalyEvent`（event_type=`aircraft_failure`，affected_aircraft 写入选中飞机）
  2. 调用已有 `recovery_service.generate_recovery_plan()` → 排除故障飞机
  3. 生成 `AircraftExclusionRecovery` 方案
  4. 用户确认后调用 `execute_plan()` → 已有流程接管
- **效果**：故障飞机被排除，其航班重新分配，覆盖不足则 DELAYED / CANCELLED

## 第五阶段：旅客流仿真（2 天）

### 旅客状态机
```
CHECK_IN → SECURITY → BOARDING → IN_FLIGHT
                                       ↓
ARRIVAL → BAGGAGE → EXIT    中转 → CHECK_IN(下游)
```

- **CHECK_IN → SECURITY**：30min 缓冲
- **BOARDING**：起飞前 30min 关闭
- **旅客分配**：窄体 160 人、宽体 280 人，按机型随机生成
- **中转旅客**：按到达/出发时间差筛选可衔接航班，随机分配 5%-20% 旅客为中转

### 延误传播与异常事件联动
- **场景 1 — 飞机故障**：飞机排除 → 航班取消/延误 → 旅客滞留
- **场景 2 — 机组请假**：替班成功 → 旅客无感知；替班不足 → 航班延误 → 旅客受影响
- **场景 3 — 机场异常**：容量下降 → 多航班 DELAYED / CANCELLED → 大量旅客滞留
- **场景 4 — 天气恶化**：区域天气变差 → 连锁延误 → 中转断联 → 下游航班客座率下降

### 旅客统计卡片（仪表盘扩展）
- 在途旅客总数
- 各机场滞留旅客数（柱状图）
- 中转断联次数
- 因异常事件受影响的旅客数

## 不做的事情

- WebSocket 推送 → 先用轮询，后续迭代
- 真实气象数据 → 使用随机生成
- 多机型性能表（油耗、各机型巡航速度差异）→ 固定巡航速度
- 地服车辆调度（加油/配餐/清洁）
- 航班时刻表编辑器
- 航线网络拓扑图
