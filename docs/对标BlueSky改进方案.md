# 对标 BlueSky 改进方案（约一周工作量）

> 项目：民航智能调度与仿真系统（job-data-visualization-team-master）
> 对标对象：BlueSky（TU Delft / NASA 开源空管仿真器，MIT 协议）
> 编制目的：借鉴 BlueSky 的优秀设计，列出可在一周内落地的改进点，含现状分析、方案、工作量与验收标准。
> 绝对边界：不能改崩现有功能，保证现有所有功能可用基础上再说改进
---

## 一、对标分析：BlueSky 的 8 项优秀设计 vs 本系统现状

| # | BlueSky 优秀设计 | 说明 | 本系统现状 | 差距 |
|---|-----------------|------|-----------|------|
| 1 | **场景文件（.scn）** | 文本命令 + 时间戳，逐行执行，"多次执行结果完全一致"，可保存/复现 | 仿真全靠 GUI 手动操作，无录制/回放能力 | 大 |
| 2 | **命令控制台（Command Window）** | 命令行是主要交互方式，`HELP` 可查命令，支持脚本化与运行时修改 | 仅按钮点击，无命令行入口 | 大 |
| 3 | **快时仿真（Fast-time）** | 以恒定步长"尽可能快地"跑完仿真，支持批量实验 | 仅有实时倍速（1x/2x/5x/10x），无批量/快速模式 | 中 |
| 4 | **多仿真节点并行** | 多个仿真并行运行、可切换显示、对比结果 | 单例引擎，无法并行对比 | 中 |
| 5 | **插件化架构** | Python 插件栈（stack commands），社区可扩展功能（如 AMAN 插件） | 功能硬编码，新增异常/策略需改源码 | 中 |
| 6 | **航迹级仿真（LNAV/VNAV）** | 飞机沿航路点飞行，含爬升/巡航/下降剖面、自动驾驶 | 两点直线动画 + 固定阶段时长，无高度剖面 | 中 |
| 7 | **风场（3D Wind Field）** | 风向量场影响航迹，可模拟逆顺风 | 天气只按省份改变"容量→延误/取消"，不影响航时 | 中 |
| 8 | **飞机性能模型（BADA）** | 机型性能数据（油耗、推力、速度剖面） | 巡航速度常数 + 阶段时长常量 | 小 |

## 二、改进点清单（共 6 项，合计约 7 个工作日）

> 优先级：P0 = 核心可交付，P1 = 增强，P2 = 锦上添花。

### 改进点 1【P0】仿真场景录制与回放（Scenario Record & Replay）

**对标设计**：BlueSky 场景文件把"时间戳 + 命令"落成文件，`IC xxx.scn` 一行即可完全复现任意仿真。可复现性是仿真工具的底线能力。

**现状问题**：当前仿真的启动、倍速、跳转、异常注入、天气设置都只能手动操作，无法保存、分享、复现一次演示，演示效果不可验证。

**改进方案**：
1. 定义 JSON 场景文件格式（等价 .scn）：
   ```json
   {
     "name": "暴雨恢复演示",
     "seed": 42,
     "clock": {"speed": 5, "jump_to_min": 720},
     "events": [
       {"t": 60,  "action": "inject_airport", "args": {"airport": "成都", "ratio": 0.5, "duration": 120}},
       {"t": 90,  "action": "weather_set",    "args": {"province": "四川", "type": "rain_heavy"}},
       {"t": 240, "action": "recovery_execute","args": {"plan_id": 1}},
       {"t": 300, "action": "speed",          "args": {"speed": 10}}
     ]
   }
   ```
2. 后端新增接口：
   - `POST /api/simulation/scenario/record`：开启录制，把引擎所有控制动作与注入事件按业务时间写入场景。
   - `POST /api/simulation/scenario/replay`：传入场景 JSON，顺序执行事件（等价 BlueSky 逐行执行 .scn）。
   - `GET /api/simulation/scenario/list` / `DELETE`：场景文件管理（存于 `data/scenarios/`）。
3. 前端在模拟大引擎增加"录制 / 停止 / 回放 / 加载场景"按钮组，回放时走引擎 `sync_to` 确定性重算。
4. **前置依赖：仿真确定性改造**（见改进点 4），保证"同一场景 + 同一 seed → 完全一致结果"。

**工作量**：1.5 天（含前端 UI 0.5 天）。
**验收标准**：录制一次完整演示 → 回放 3 次，KPI 序列完全一致；场景文件可在另一台机器复现。

---

### 改进点 2【P0】仿真命令控制台（Command Console）

**对标设计**：BlueSky 命令窗口是主交互界面，`IC/PAN/SPD/ALT/HELP` 等文本命令 + Tab 补全，方便脚本化与教学演示。

**现状问题**：所有操作依赖鼠标点击，无法"一句话"控制仿真，演示节奏受 GUI 操作限制。

**改进方案**：
1. 模拟大引擎与航班模拟页底部增加命令行输入框（可展开/收起）。
2. 后端新增 `POST /api/simulation/console`（参数 `command`），统一命令解析：
   - 时间控制：`PLAY` / `PAUSE` / `RESUME` / `STOP` / `SPEED 5` / `JUMP 50`（百分比）
   - 事件注入：`INJECT AIRPORT 成都 0.5 120`、`INJECT CREW 王小明 09:00 18:00`、`INJECT ACFT B-3001 120`
   - 天气：`WEATHER 四川 RAIN_HEAVY`、`WEATHER CLEAR`
   - 场景：`SCENARIO SAVE demo1`、`SCENARIO LOAD demo1`、`SCENARIO RECORD ON/OFF`
   - 帮助：`HELP` 列出全部命令与用法（对齐 BlueSky `HELP`）
3. 命令解析采用注册表模式（dict 命令名 → 处理器），为后续插件化打基础。

**工作量**：1 天。
**验收标准**：`HELP` 可查全部命令；每条命令与 GUI 操作等价（用命令能完整复现一次注入-恢复演示）。

---

### 改进点 3【P0】快时批量仿真与实验对比（Fast-time & Batch Experiment）

**对标设计**：BlueSky 快时模式以恒定步长尽可能快地跑完仿真；多节点并行仿真可对比结果。科研/教学最常用"跑 N 组实验对比指标"。

**现状问题**：仿真只能实时观察，无法批量跑完一个"7 天"业务周期并导出统计；不同策略/天气下的效果只能凭感觉。

**改进方案**：
1. 后端 `simulation_engine` 增加 **fast-time 模式**：`start_fast(target_minutes)` 关闭线程 sleep，每 tick 直接推进至目标时刻（复用 `_do_tick` 逻辑，保证与实时模式行为一致）。
2. 新增接口 `POST /api/simulation/batch`，输入实验矩阵（如 `[{"weather":"rain_heavy","seed":1}, {"weather":"rain_heavy","seed":2}]`），串行跑完并返回每次实验的 KPI 汇总（准点率/完成率/取消数/平均延误/总旅客影响）。
3. 前端新增"实验对比"面板（放在模拟大引擎）：选择对比维度（天气/策略/seed）→ 一键批量执行 → 多组 KPI 柱状/折线对比图，支持导出 CSV。
4. 结果为每次实验生成 run 记录，支持与历史 run 对比（对齐 BlueSky 多节点对比思想，轻量实现）。

**工作量**：1 天（前端 0.5 + 后端 0.5）。
**验收标准**：可批量跑 3 组不同天气的实验，1 分钟内全部完成并输出对比图表。

---

### 改进点 4【P0】仿真确定性改造（固定随机种子）

**对标设计**：BlueSky 场景文件"多次执行结果完全一致"，前提是仿真确定性。

**现状问题**：引擎中起飞延误采用概率随机（`random.random()` 判断容量 <0.5），前端天气推演含随机对流闪动；同一操作两次运行结果可能不同，无法做科学对比与回放。

**改进方案**：
1. 引擎所有随机源统一收敛到可注入的 `random.Random(seed)`（`simulation_engine` 初始化参数增加 `seed`，默认 42）。
2. 天气中断计算改为确定性：时间线优先取 `t=0` 时刻快照（当前实现已有该倾向），消除随机对流抖动；必要时提供"确定性开关"。
3. 随机延误改为"按 seed 生成延误决策表"，回放时按 seed 复现完全一致。

**工作量**：0.5 天（是改进点 1/3 的前置）。
**验收标准**：相同 seed 下，两次运行 KPI 快照序列完全一致；不同 seed 结果有差异但分布合理。

---

### 改进点 5【P1】航迹高度剖面与风场影响可视化

**对标设计**：BlueSky 支持航路点 LNAV/VNAV 自动驾驶、高度剖面，以及 3D 风场影响航迹与航时。这是从"看动画"到"看真实飞行"的关键。

**现状问题**：航班地图上飞机只是两点直线匀速动画，无爬升/巡航/下降剖面；天气只影响延误/取消，不体现绕飞/逆风导致的航时变化。

**改进方案**（控制在 1.5 天内的轻量实现）：
1. **高度剖面动画**：按现有 `PHASE_DURATION`（爬升/巡航/下降）在 3D 地图上绘制飞机高度曲线，机模位置与高度联动，信息卡/仪表盘显示当前高度。
2. **风场影响**：后端为航班增加 `wind_effect`（顺风/逆风 ±航时），按省份天气映射"风分量"（雷暴/大雨 → 逆风或绕飞 + 航时）；前端地图按省份绘制风向箭头场（复用天气层）。
3. 天气中断 meta 中增加 `delay_reason: 'headwind' | 'detour'`，在航班调整面板展示"绕飞/逆风"原因。

**工作量**：1.5 天。
**验收标准**：地图上飞机高度随时间呈"爬升-巡航-下降"剖面；四川雷暴时成都相关航班出现"绕飞延误"且地图显示风场箭头。

---

### 改进点 6【P1】异常模板与恢复策略配置化（轻量插件化）

**对标设计**：BlueSky 通过 Python 插件栈扩展功能，新增能力不需要改核心代码。这是其社区生态活跃的根本原因。

**现状问题**：`scenario_templates.py` 的模板字典和 `recovery_strategies/` 的 6 个策略类全部硬编码在源码里，新增一个场景或策略需要改代码、改接口、重启动。

**改进方案**（轻量插件化，不引入完整插件框架）：
1. 异常模板 JSON 化：把模板库迁移到 `backend/data/anomaly_templates.json`，启动时加载；新增模板无需改代码。
2. 恢复策略注册表：把 6 个策略类注册到统一 `STRATEGY_REGISTRY`（策略名 → 类 + 适用事件类型），`generate_recovery_plan` 按事件类型查表调用；后续新增策略只需新增类并注册。
3. 暴露 `POST /api/anomaly/strategies`（返回可用策略清单）与"策略启用/禁用"开关，前端异常调度页展示当前生效策略链。

**工作量**：1 天。
**验收标准**：通过修改 JSON 可新增一个异常模板并立即在前端"新建事件"中出现；注册表支持开关某个恢复策略而不影响其他功能。

## 三、一周实施计划（7 天）

| 天 | 工作内容 | 对应改进点 | 交付物 |
|----|---------|-----------|--------|
| D1 | 仿真确定性改造（seed 收敛、天气确定性）；设计场景 JSON Schema | #4 | 确定性引擎 + 场景格式文档 |
| D2 | 后端场景录制/回放接口 + 场景文件管理 | #1 | `/api/simulation/scenario/*` |
| D3 | 前端录制/回放 UI（模拟大引擎）；命令控制台后端命令解析 | #1、#2 | 场景按钮组 + 命令处理器注册表 |
| D4 | 前端命令控制台 UI（含 HELP、Tab 补全）；快时模式后端 | #2、#3 | 控制台 + `start_fast` |
| D5 | 批量实验 API + 前端实验对比面板（多 run KPI 对比 + CSV 导出） | #3 | 实验对比功能 |
| D6 | 高度剖面动画 + 风场影响与风向箭头可视化 | #5 | 航迹增强 |
| D7 | 模板/策略配置化重构；回归测试（回放一致性、批量实验）+ 更新说明书 | #6 | 配置化 + 测试报告 |

**风险与说明**：
- #4 是 #1/#3 的硬前置，务必 D1 完成；若延期则 #3 顺延。
- #5 涉及 Three.js 改造，若 D6 时间不足可降级为"仅高度剖面动画 + 延误原因标注"（风场箭头留作 D7 加分项）。
- 所有改动不破坏现有手动操作路径，回放/控制台/批量实验均为新增入口。
